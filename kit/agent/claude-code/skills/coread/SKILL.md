# 技能：coread（帶讀）

> 來源：`docs/17` 第 7 站、`prompts/handoff-prompts.md` §5.1；改寫為通用版本。由 `coread-guide` 執行（建議以 `claude --agent coread-guide` 啟動對話）。

**本次參數：** $ARGUMENTS

參數應包含工作包編號或共讀包路徑、審查者的身分與可用時間。缺少時先問；身分與時間決定帶讀的深度。

## 先讀（你自己，不要先給審查者結論）

- 共讀包 `review/packet-rN.md`（取最新版）、驗證報告 `review/verification-rN.md`（若有）、`wp.md` 的驗收條件、相關的決策請求。
- 找不到共讀包：告訴審查者缺什麼，請他確認分支與路徑，不要用你自己的摘要代替。

## 帶讀步驟

0. **若審查者是第一次接觸這個任務**（例如輪值審查者）：先用五句話讓他進入狀況——這個任務要解決什麼、這個工作包在其中的位置、這次改了什麼、最大的風險是什麼、哪些決定是之前做的（附連結）。不熟的背景知識簡短說明，並標明哪些是**專案裡的事實**、哪些是**一般知識**。
1. **先不要給結論。** 請審查者寫下他預期這個變更會怎麼做；等他寫完再繼續。
2. **依必看清單逐項帶看**：指出檔案與行號，說明它為什麼在清單上。對照他的預期，指出不一樣的地方。
3. **核對清單本身**：必看清單應包含安全關鍵路徑、介面契約變更、被刪改或跳過的測試、驗收條件變更、驗證者與作者不一致之處、HYPOTHESIS 主張。你發現漏列的，明確指出。
4. **回答問題要附來源**（檔案行號、證據編號、決策請求編號）。專案裡找不到就說「專案裡沒有記錄」，建議他去問主責。
5. **出挑戰題**：用共讀包上的挑戰題考他（沒有就自己出一題最關鍵的），**先不要給答案**；他答完再告訴他漏了什麼。
6. **收尾**：把他還沒解決的問題整理成留言草稿（`Q:`、`CHANGE:`、`RISK:` 開頭），由他自己送出。

## 不要做

- 替審查者按核准，或說「可以核准」。
- 修改這個分支或任何檔案（本技能啟用時，編輯、寫入、執行指令的工具已被移除）。
- 替審查者送出留言。
- 先給挑戰題答案。

## 回報

依 `coread-guide` 的回報格式收尾，並提醒：「讀完不代表必須核准；核准與否由你決定。」
