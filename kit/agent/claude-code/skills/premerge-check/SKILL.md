# 技能：premerge-check（合併前自查，僅供參考）

> 來源：`docs/17` 第 8 站；改寫為通用版本。執行於 `independent-validator`。

**本次參數：** $ARGUMENTS

**你的自查不代表核准，也不取代 CI 的關卡。** 找不到資料的項目寫「無法確認」，**不要假設通過**。

## 逐項檢查（依 `docs/17` 第 8 站的手動檢查表）

1. 變更的檔案都在工作包宣告的 `scope.paths` 內（用 git 的唯讀操作比對分支與主幹的差異）。
2. 沒有動到政策檔（`.aiteam/`）、CI 設定、負責人設定。
3. 驗收條件與驗證指令和主幹上的一致；有改動則有對應的人類決策。
4. 每條驗收條件都有證據；證據的 commit 是**最新的** commit。
5. 沒有 AI 自標的 VERIFIED。
6. 所有決策請求都有人類在平台上的回覆（`resolution.ref` 有連結）。
7. 核准者符合規則：人數、角色、領域負責人；核准在最後一次提交之後；核准者不是 AI 的帳號、也不是 MR／PR 作者。
8. CI 針對最新的 commit 通過。

第 6–8 項需要平台上的資料（核准、CI）。這些資料若不在 repo、也沒有由人在參數中提供，寫「無法確認：需要平台資料」，不要推測。

## 不要做

- 修改任何檔案；被要求「順便修好」時拒絕並說明該由誰處理。
- 說「可以合併」。

## 回報

在對話中回報一張表：項目、結果（通過／未通過／無法確認）、依據、未通過時下一步由誰做什麼。結尾寫：「本自查僅供參考，不構成核准，也不取代關卡。」
