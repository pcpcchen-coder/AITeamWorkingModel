# 技能：takeover-pack（接手包與交接摘要）

> 來源：`prompts/handoff-prompts.md` §5.3、§4.5；改寫為通用版本。由 `mission-executor` 執行。

**本次參數：** $ARGUMENTS

## A. 接手包（package）

前提：主責缺席，備援已依接手程序成為代理主責，**有記錄在案的交接**（請人提供連結）。沒有交接紀錄就停下來，告訴對方需要先完成交接程序（`docs/16` §5.1），不要接受方向指示。

依 `kit/templates/takeover-package.md` 產生：
- 快照：目前的 commit、介面契約版本、已接受的工作包。
- 目標與成功定義；哪些成功定義尚未被驗證。
- 環境怎麼重建。
- 最近完成與失敗的工作、如何重現。
- 進行中的 MR／PR、待決的決策請求、排定的人類任務。
- **一個代理主責可以先做的小任務**，用來確認真的接得起來。
- 缺口：專案裡找不到、只有原主責知道的事，標 UNKNOWN。

只用 repo 與 MR／PR 上的資料。**不要推測原主責的想法**；他沒寫下來的理由標「未記錄」。設備相關的步驟不可用猜測的指令代替程序（標 UNKNOWN，指向實驗室 SOP）。

## B. 對話交接摘要（handoff）

寫一份讓完全沒有前文的 Agent 能接手的摘要，存到本工作包的工作目錄（例：`handoff-<日期>.md`），不要只留在對話裡：
- 任務與工作包編號、目的。
- 目前的分支、MR／PR、最新的 commit。
- 已完成與未完成的驗收條件，各附證據位置。
- 已做的決定（附決策請求編號與人的理由）。
- 試過但不可行的作法，以及原因。
- 目前卡在哪、下一步是什麼。
- 你做過但尚未驗證的假設。

只寫事實；不確定的事標示不確定。

## 不要做

- 推測原主責的想法或補上沒記錄的理由。
- 把接手包寫成「讀完就能接手」的保證；能不能接手由演練與人判斷。

## 回報

用 `mission-executor` 的回報格式；第 3 項「沒做什麼」列出所有 UNKNOWN 與「未記錄」的缺口。
