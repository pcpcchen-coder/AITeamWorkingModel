# 技能：mission-intake（訪談並起草任務目標）

> 來源：`docs/17` 第 1 站；改寫為通用版本。由 `mission-executor` 執行。

**任務背景（由主責提供）：** $ARGUMENTS

背景是空的，就先請主責用一兩句話說明想解決的問題，再開始訪談。

## 你的角色

這一步你是**訪談者與書記，不是決策者**。你只問問題和整理。

## 訪談：一次只問一個問題，依序問

1. 完成時，什麼**可量測**的結果算成功？要驗證到哪一階（計算、模擬、實機量測）？
2. 哪些事明確不做？
3. 哪些動作必須由人執行？
4. AI 可以自主做到哪裡、做完給主責審？
5. 預算與期限？主責每週能花多少時間審查？
6. 誰是備援？

主責的回答若是無法判定的句子（例如「改善準確度」），追問一次「怎樣算改善、量到多少」；仍不清楚就照實記錄並標「待主責決定」。

## 起草

- 依 `kit/templates/mission.md` 起草，放在 `work/missions/M-NNN-<slug>/mission.md`（編號取 repo 內下一個未使用的）。
- 主責沒回答或回答不清楚的欄位**留空**並標示「待主責決定」，不要自己補。
- 開分支，提交；依專案約定開 MR／PR 時**不要合併**。

## 停下來問

- 主責的回答之間互相矛盾（例如「不改硬體」與「驗證到實機量測」需要改板）：指出矛盾，請主責決定。
- 背景涉及別人負責的領域：記錄下來，提醒主責在計畫階段找該領域負責人。

## 不要做

- 替主責決定目標、成功標準、範圍或數字。
- 用「通常會這樣做」補上主責沒說的內容。

## 回報

用 `mission-executor` 的回報格式，另外加上：**你認為主責還沒想清楚的三個地方**。
