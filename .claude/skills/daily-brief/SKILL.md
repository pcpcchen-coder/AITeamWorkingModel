# 技能：daily-brief（每日簡報）

> 來源：`prompts/handoff-prompts.md` §6.1；改寫為通用版本。執行於 `cadence-reporter`。

**本次參數：** $ARGUMENTS

參數第一項是要給誰的簡報（成員代號或平台帳號）。缺少時判為無法產生，請人提供，不要自己挑一個人。

## 資料來源

- repo 內：`work/missions/**` 的任務、工作包（狀態、`blocked`）、決策請求（`resolution` 是否為空、`needed_by`）、人類任務紀錄（`status`、`executor`）；角色矩陣（找出此人擔任主責、備援、領域負責人的地方）；git 歷史（昨天被合併的變更）。
- 平台上的資料（待審的 MR／PR、留言）：若專案有已登入的平台 CLI，用唯讀查詢取得；沒有就寫「平台資料未取得」，只用 repo 內的資料。

## 格式（不超過一個螢幕）

```
【等我決定】待我審的計畫與共讀包、未回覆的決策請求。各附到期日與「不處理會卡住什麼」。
【等我動手】指派給我的人類任務。
【昨天完成】被接受的工作包。
【AI 接下來會做】除非我另有指示（只列 repo 中寫明的下一步）。
【注意】我的待審件數與上限；逾期的項目。
```

## 規則

- 只列事實並附連結或檔案路徑。沒有的段落寫「無」。
- 不寫進度百分比；不評價任何人。
- 預設只輸出在對話中，不寫檔。

## 回報

簡報本身，加上 `cadence-reporter` 回報格式的第 3–5 項（資料來源與 commit、缺漏、不確定的地方）。
