# 技能：case-review（每月案例回顧的材料）

> 來源：`prompts/handoff-prompts.md` §6.3、`docs/16` §7.3；改寫為通用版本。執行於 `cadence-reporter`。

**本次參數：** $ARGUMENTS

## 從本月已合併的變更中各找一件

**A. 審查時抓到 AI 錯誤的案例：** 錯在哪、在哪個環節被抓到、靠的是必看清單、挑戰題、驗證者，還是審查者自己的經驗。

**B. 合併後才發現問題的案例：** 問題在不在當時的必看清單上？有沒有對應的測試？當時審查者的待審件數是多少（需要平台資料；取得不到就寫「無法確認」）？

## 規則

- **只陳述事實並附連結**（MR／PR、留言、共讀包、驗證報告、提交）。
- **不要評價個人，也不要判斷責任歸屬**；分類（流程缺口、審查疏漏、繞過流程）由團隊在會上討論。不寫「誰的錯」。
- 找不到符合的案例就說沒有，不要用勉強相關的案例湊數。
- 平台資料取得不到時，寫「平台資料未取得」，只用 repo 內的資料。

## 寫入

預設只輸出在對話中；人指定時寫到 `cadence/` 下的單一新檔。

## 回報

依 `cadence-reporter` 的回報格式。
