# 06 — 90 天轉型路線圖與量化驗收

**原則：** 同時改流程與工具，但不要先建立龐大的 AI 管理平台。以 2–3 個不同型態的試點逐步證實價值。

## 1. 12 週導入節點

| 週次 | 系統交付 | 組織/流程交付 | Exit criteria |
|---|---|---|---|
| W1–W2 | Git/Issue connector PoC、本地 LLM benchmark、資料分級 | 盤點專案、Primary/Backup、單點風險 | 確定 2–3 個試點與至少 50 個評測問題 |
| W3–W4 | 基礎 RAG、帶來源的回答、任務狀態 schema | 訂定人類核准 gate、研究資料範圍 | 引用能追到版本化原始來源；ACL 測試通過 |
| W5–W6 | 自動事件摘要、AI task graph、假資料共讀 UI | Primary/Backup 共同評審 AI 的計畫 | AI 完成工作可回放，重要決策不被自動略過 |
| W7–W8 | 真實專案 Mission Control、評論與決策稽核 | Backup 每週精簡共讀，量測投入時間 | 事件去重、評論版本固定、決策可查 |
| W9–W10 | Takeover package generator、沙盒 runner | Backup 首次獨立演練 | 至少 1 個真實可重現接手案例 |
| W11–W12 | Portfolio 看板、評測、故障與復原測試 | 改善制度，決定擴大範圍 | KPI 有真實基準，安全測試通過，決策記錄完成 |

依環境、人員、採購與安全審批調整，並非承諾日程。

## 2. 試點選擇

- **軟體型**：已有 Git/CI，可快速驗證自動化與接手。
- **演算法型**：驗證資料集、模型假設與重現性。
- **實驗型**：驗證設備 SOP、實驗 manifest 與安全核准。
- 優先選有真實工作、願意參與的 Primary/Backup，以及已可取用的資料；避免只有示範性的假任務。

## 3. KPI（先測基準，再設定目標）

| 指標 | 定義 / 計算 | 試行目標（可調整） |
|---|---|---|
| 備援覆蓋率 | 有已驗證 L2+ Backup 的重要項目 / 重要項目總數 | ≥80%，高風險專案優先 |
| 接手演練通過率 | 完成有證據任務的演練 / 全部演練 | ≥80% |
| 有效接手時間 | 獲取接手包 → 完成第一個驗證產出 | 軟體試點 ≤1 工作天 |
| Backup 日常投入 | 每週 digest/審閱工時（不含每月演練） | 約 5–10 分鐘／週 |
| Primary 追加行政負擔 | 因 AI 管理新增的人工時間 | ≤15 分鐘／週（初期目標） |
| 重要結論可追溯率 | 有原始資料/測試/決策引用的重要結論數 / 總數 | ≥95% |
| AI 錯誤採納率 | 被正式採納但後來證實錯誤的 AI 結論 / 採納結論 | 追蹤且持續降低 |
| 自動任務完成率 | 在預授權範圍內符合 Definition of Done 的任務 / 自動任務 | 先建立基準，不盲目追高 |
| 安全越權次數 | 審計確認的不當存取/寫入/外傳 | 0 |

**不要把 LLM 自評當 KPI。** KPI 應由 workflow events、審查決策與可重現測試計算，抽樣核對原始證據。

## 4. 成本與產能評估

必須同時計入：
- 人員：Primary 審核、Backup 演練、資料清理、模型維運。
- 計算：GPU、電力、記憶體、併發、儲存、備份。
- 品質：LLM 幻覺、錯誤工具呼叫、回歸測試與安全審批。
- 效益：接手恢復時間、重複調查/重建工作減少、交付吞吐、研究可重現性。

比較至少三種條件：A 既有單人工作、B 傳統雙人備援、C AI-driven + 精簡 Backup。以相同技術難度、相同時間窗做比較；避免把不具可比性的專案直接相減。

## 5. 風險與應對

| 風險 | 應對 |
|---|---|
| 人員覺得審核 AI 比自己做更花時間 | 先挑適合自動化的任務，導入異常優先審查 |
| AI 摘要不可信 | Evidence-aware RAG + 來源引用 + UNKNOWN + 人工抽驗 |
| 本地 LLM 速度不足 | benchmark、模型分工、快取、batching、GPU 容量規劃 |
| 備援只會看摘要不會做 | 每月真實沙盒演練；L2/L3 只能用證據授予 |
| 敏感研發資料被同步外部服務 | 資料分級、模型端點管控、出網限制與稽核 |
| 共讀分歧無人決策 | 設 Primary 最終責任、升級機制與到期提醒 |
| 原始實驗資料不完整 | manifest、校正／環境欄位必填及重大缺口提示 |

## 6. Go / No-Go

繼續擴大導入的最低條件：
1. 至少 2 個不同型態的試點成功完成 AI 任務 + 人類共讀與核准。
2. 至少 1 個 Backup 完成正式獨立演練，並可回放證據。
3. RAG 跨專案權限測試、模型故障處理、審計測試通過。
4. 工時與可追溯性有原始基準／試點結果，而非主觀感受。
5. 經研究主管與 IT/資安確認下一階段資料分類與部署條件。
