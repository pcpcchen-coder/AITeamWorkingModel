# 01 — AI-Driven R&D 組織與工作模式

**文件狀態：** 設計提案 v0.2 · 2026-11-13

## 1. 轉型緣由

研究團隊常採單人主責一項研究／子系統；人員異動時會出現「技術單點故障」：程式與報告雖保留，研究假設、實驗脈絡、設備習慣與未解決問題卻難以接手。

舊模式：個人持有脈絡 → 人員離開才交接。
過渡模式：Primary 開發 + Backup 同步 + AI Shadow 記錄。
**目標模式：AI Agents 推進已授權的工作，Primary / Backup 共讀同一份 AI 產出與證據，並共同維持組織研發能力。**

## 2. 設計原則

1. **共享的是研發能力，不是每位員工必須知道全部細節。**
2. **人類設定研究目標、風險邊界、批准關鍵決策；AI 在邊界內執行。**
3. **成果與驗證證據先於進度口頭宣稱。** 不能以「AI 說完成」等同任務完成。
4. **Backup 不必重複主責工作。** 使用差異摘要 + 按需 AI 問答 + 定期實戰，降低日常投入。
5. **人類仍對研究正確性、安全與合規負責。** AI 不能自動取得對外發布、設備操作、正式部署權限。
6. **知識獨立於模型／對話工具。** 原始碼、版本化實驗、決策、測試證據才是 Source of Truth。
7. **研究探索需要不確定性標示。** 已確認事實、假設、AI 建議、未知、已否決方案要清楚區別。

## 3. 角色與責任

| 角色 | 核心責任 | 不需要做什麼 | 關鍵交付 |
|---|---|---|---|
| Research Owner / Primary | 設目標、核准計畫、掌握技術邊界與風險、做關鍵決策 | 逐條手工寫進度、親自執行所有重複工作 | 已核准的計畫、決策與研究結果 |
| Secondary Technical Owner / Backup | 共讀關鍵差異、挑戰假設、確認接手入口、完成獨立演練 | 每天跟著主責寫同樣的程式、逐行閱讀全部紀錄 | 審查問題、接手驗證紀錄 |
| AI Project Lead / Orchestrator | 規劃與分派任務、管控範圍、生成可追蹤狀態、提出決策請求 | 未經授權直接批准安全敏感變更 | Task graph、狀態事件、證據連結 |
| Research Agent | 文獻、專利、方案、模型假設與驗證建議 | 把未驗證推論寫成既定事實 | 研究備忘、來源、信心和缺口 |
| Engineer Agent | 程式、模擬、測試腳本與可審查 PR | 在正式環境無審核執行更動 | 版本化差異、測試與回退方法 |
| Validator Agent | 獨立測試、異常分析、證據核對 | 只重述開發 Agent 的結論 | 可重現的驗證報告、未測範圍 |
| Handover Agent | 技術摘要、FAQ、接手包、能力缺口 | 沒有來源就回答為確定 | Takeover package |
| Manager / Reviewer | 優先順序、資源、風險、評估雙人能力 | 把「有填 Backup」當成覆蓋完成 | 風險看板與改善決策 |

小團隊可由同一人擔任多種人類角色，但**重要驗證必須避免同人自我核准**；同一個 LLM 的兩種人格也不能當成真正獨立的驗證來源。

## 4. Backup 成熟度（以證據評級）

| 等級 | 定義 | 達標驗收 |
|---|---|---|
| L0 | 無接手能力 | 無 |
| L1 | 能找到可信的程式、文件、設備與窗口 | 在限定時間內定位來源及狀態 |
| L2 | 能在隔離或授權環境獨立重現案例 | 在不詢問 Primary 下完成環境重建、執行測試、解釋結果 |
| L3 | 能獨立延續下一階段工作並處理異常 | 成功完成真實小型研究／修復任務，有外部審核證據 |

- **目標值：** 一般重要項目至少 L2；高關鍵性項目優先 L3。
- **禁止事項：** 只閱讀 AI 摘要或出席會議，不可升級到 L2/L3。
- **有效期：** 長期無操作的能力須定期重新驗證；技術變更後可降低級別。

## 5. 日常人力負擔設計（試行假設）

- Primary：每週只處理 AI 篩選出的重大變更、風險或需要核准項目；目標額外行政成本 ≤15 分鐘。
- Backup：每週閱讀 3–5 條重要變化與 1 個待思考問題；目標 5–10 分鐘。重要設計變更另行審查。
- 每月：安排 30–60 分鐘獨立接手演練；實驗設備及高風險研究依實際需求調整。
- 主管：每雙週看風險、接手演練與資料可追溯性，非要求團隊手工重寫報告。

上述是改善方向，需先量測原始投入，不保證立即達標。

## 6. 組織能力圖

記錄「技術能力 × 專案 × 人員 × 實證級別 × 最近演練日期 × 依賴資源」。不只記人名：
- 哪些項目 Primary 與 Backup 都依賴同一台設備／帳號／外部專家？
- 哪些領域只有一個人能判斷研究結論？
- AI 能協助重現哪些過程？哪些只能靠認證人員及實體設備？

優先處理高影響且 L0/L1 的單點依賴，不要把所有專案平均分配備援工時。

## 7. 研究單位特別注意

- 軟體：可測試環境、依賴鎖定、API 契約、回歸測試。
- 演算法：模型假設、資料集版本、參數與訓練／評估條件、失敗案例。
- 電力電子／電池：設備、校正、接線、測試條件、批次、波形與安全 SOP；AI 不得自行驅動高風險儀器。
- 系統整合：網路、韌體、機電介面、部署與故障復原。
- 所有類型都需保存「為什麼做／為什麼不做」的設計決策（ADR）。

**成功定義：** 人員缺席時，團隊不依賴其個人記憶，就能在允許的時間內恢復可驗證的研發工作。
