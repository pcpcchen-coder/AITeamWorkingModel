共讀共推流程示範

AI 執行開發，人類在平台上共同審查並推進進度。按「下一步」跟著一個橫跨軟體、韌體、硬體的案例走完一輪；在標示可操作的站點，你可以自己做決定。每一站都附上可以直接交給 AI 的話、由哪個 Agent 負責，以及人要確認的事。往下還有各領域的交付範例、四個 Agent 的分工，與多人協作的三個小工具。

示範用虛構案例：專案、人員、數值、指令輸出皆為設計示意，非真實結果；aitw 工具尚未實作

人類AI AgentCI 與 Gate

把工作交給 AI

上面每一站的範例是同一個案例。換成你自己的任務時，三個領域各有一定要多講的事；而 AI 的介入可以收斂成四個角色。

各領域怎麼交付

選領域與任務類型，看交付的寫法。這是摘要版；完整範例在 docs/18。

你對 AI 說的話（範例）
方括號是要你填的內容。範例未經實測；硬體範例以匯出檔（網表、BOM、PDF）為輸入。

        
這個領域審查者最該確認
    
      
    
    
    
    
    
      
    四個 Agent，各管各的
    
      
    不是每個介入點一個 Agent。只有需要獨立性、權限不同、服務對象不同或觸發方式不同時才拆開。
    
      
    
      
    
      
    
        
    不做成 Agent 的事
    
        
    
          
    關卡檢查
    由確定性的 CI 執行。關卡要每次給出同樣的答案，不能交給會變動的模型判斷。
    
          
    決定、核准、合併
    人。核准的正本是人在平台上的已驗證行為。
    
          
    軟韌硬的差異
    用領域規則與交付內容處理，不各立一個 Agent。
    
        
    
        
    
      
    
        
    安裝與現況
    
        
    
          
    安裝
    把 kit/agent/claude-code 的 agents 與 skills 複製到專案的 .claude/，放入樣板，並把常駐規則寫進 AGENTS.md。GitLab 與 GitHub 作法相同。
    
          
    現況
    四個 Agent 與 21 個技能已建立（Claude Code）。每個 Agent 只在虛構的小例子上試跑過一次，且用的是同一個模型；尚未在真實專案上試用。
    
          
    真正的保證
    不可逆的限制（不能合併、不能碰設備）要靠帳號權限與執行環境，不是靠 Agent 的定義。
    
        
    
      
    
    
    
  
    

  
    
    
    多位成員一起工作時
    
    
    上面的案例只有一個任務。四個人、三個任務同時進行時，問題變成：誰審誰的產出、要求互相矛盾時誰決定、出錯怎麼算。團隊的產能上限是人的審查容量，不是 AI 的產能。
    
  
    

  
    
    
    
      
    這件該由誰審
    
      
    主責審自己任務的 AI 產出，是把關自己的產出，不算獨立審查。選一個情況，看規則怎麼排人。
    
      
    
      
    
        
    
          
    
          
    
        
    
        
    
          
    
          
    
        
    
        
    
        
    
      
    
    
    
    
    
      
    要求互相矛盾時
    
      
    人與人之間的分歧不交給 AI 調解。選一種爭議，看 AI 怎麼做、由誰決定。
    
      
    
      
    
      
    
        
    出錯了，先分類再處理
    
        
    預設不究責個人，但界線清楚。選一個情況。
    
        
    
        
    
      
    
    
    
  
    

  
    
    
    
      
    Gate 模擬器
    
      
    合併前的機器檢查。調整條件，看哪一項會被擋下、下一步該誰做。
    
      
    
        
    
          
    
        
    
        
    
        
    
      
    
    
    
    
    
      
    三個領域，AI 能做到哪一階
    
      
    驗證由便宜到昂貴分五階。藍色由 AI 與 CI 完成；橘色必須由人執行。點任一格看說明。
